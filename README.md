# PackageDependencies

Консольное приложение на языке Go для анализа и визуализации графа зависимостей npm-пакетов.

## Возможности

- Настройка параметров анализа через командную строку.
- Получение информации о зависимостях npm-пакетов.
- Построение графа транзитивных зависимостей.
- Обнаружение циклических зависимостей.
- Ограничение глубины анализа.
- Вывод графа зависимостей в виде ASCII-дерева.
- Тестирование с использованием локальных JSON-файлов.

## Структура проекта

- `src/` — исходный код приложения.
- `tests/` — JSON-файлы с тестовыми графами зависимостей.
- `run.bat` — запуск в Windows.
- `run.sh` — запуск в Linux.

## Запуск

Windows:

```powershell
.\run.bat --package lodash --repository https://registry.npmjs.org
```

Linux:

```bash
./run.sh --package lodash --repository https://registry.npmjs.org
```

## Параметры командной строки

- `--package` — имя анализируемого пакета.
- `--repository` — URL npm-репозитория или путь к локальному тестовому файлу.
- `--test-mode` — режим работы с локальным JSON-файлом. По умолчанию `false`.
- `--ascii-tree` — параметр для управления ASCII-выводом графа.
- `--max-depth` — максимальная глубина анализа зависимостей. По умолчанию `3`.

## Этап 2. Сбор данных

На данном этапе реализовано получение информации о зависимостях npm-пакетов напрямую из репозитория.

Программа выполняет следующие действия:

- Отправляет HTTP-запрос к указанному npm-репозиторию.
- Получает метаданные пакета в формате JSON.
- Определяет последнюю опубликованную версию пакета.
- Извлекает список его прямых зависимостей и требования к их версиям.
- Выводит зависимости в алфавитном порядке.
- Обрабатывает ошибки сетевых запросов, HTTP-ответов и декодирования JSON.

Для получения данных используются стандартные библиотеки Go. Менеджеры пакетов и сторонние библиотеки для получения информации о зависимостях не используются.

## Этап 3. Построение графа зависимостей

На данном этапе реализовано построение графа транзитивных зависимостей с использованием алгоритма поиска в глубину (DFS) без рекурсии.

Основные возможности:

- Построение графа зависимостей, включая транзитивные зависимости.
- Использование явного стека для обхода графа.
- Обнаружение циклических зависимостей.
- Ограничение глубины обхода с помощью параметра `--max-depth`.
- Обработка общих зависимостей, встречающихся в нескольких ветвях графа.
- Вывод результата в виде ASCII-дерева.
- Использование локальных JSON-файлов вместо реального npm-репозитория в тестовом режиме.
- Проверка корректности тестового репозитория и имен пакетов.

Пример запуска в тестовом режиме:

```powershell
go run ./src --package A --repository tests/normal.json --test-mode=true --max-depth 3
```

Для тестирования предусмотрены отдельные JSON-файлы, описывающие различные ситуации: обычный граф, общие зависимости, циклы, ограничение глубины и другие случаи.

## Этап 4. Дополнительные операции

На данном этапе реализован алгоритм определения порядка загрузки пакетов с использованием обхода графа зависимостей в глубину (DFS).

Для построения порядка загрузки используется алгоритм с явным стеком. Пакеты добавляются в результат после обработки всех их зависимостей. Таким образом, зависимости располагаются раньше пакетов, которые от них зависят.

Также реализована проверка циклических зависимостей. Если в графе обнаружен цикл, программа сообщает об ошибке и не формирует порядок загрузки.

Для проверки работы алгоритма использовались тестовые репозитории с обычными, общими и циклическими зависимостями, а также репозиторий npm.

При сравнении с npm проверялась структура зависимостей и порядок, в котором зависимости должны загружаться. В случаях, когда результаты отличались по глубине отображения, это объяснялось ограничением максимальной глубины анализа, заданным параметром `--max-depth`.

## Этапы разработки

1. Прототип командной строки и проверка параметров.
2. Получение непосредственных зависимостей npm-пакетов.
3. Построение графа транзитивных зависимостей.
4. Определение порядка загрузки пакетов.
5. Визуализация графа зависимостей с помощью D2 и ASCII-дерева.
